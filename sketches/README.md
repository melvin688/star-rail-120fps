# UI 重设计提案

四份可交互的 HTML 稿，浏览器直接打开即可点击。三套是主界面排版，一套是帧率小窗。

背景：现有界面 476×771，三张卡片里塞了 13 个按钮，主按钮裸露在卡外，各行控件的左边缘在 181/196 之间跳，尺寸和位置两组的宽度还不一致。小窗是 `FormBorderStyle=None` + `ShowInTaskbar=false`，**没有任何可见的关闭方式**——只有 `Ctrl+Alt+F` 和右键菜单，两个都藏得太深。

## 001 · 严格网格（单列）

宽 480。一张卡里同时放状态和主操作，主按钮从卡外挪进来，和「目标帧率」共用同一套 84px 标签列。

- 所有行的左边缘统一到同一个 x，实测唯一值 181
- 两个主按钮等宽 199.5
- 分段控件等宽 304、右边缘统一 579
- 卡片间距与页头间距都是 14
- 注意事项默认折叠

适合：改动最小，和现有卡片流结构最接近，设置项一眼全见。

## 002 · 双列宽屏

宽 780。左列是状态 + 主操作，右列是小窗设置 + 注意事项。两列各自一套网格，互不干扰。

- 左列 320px：状态数字 52pt 作锚点，下面直接跟两个全宽按钮
- 右列自适应：三个分段控件等宽 185，右边缘统一 683
- 信息一眼看全，不用滚动

代价：窗口从 480 变 780，1080p 屏上占掉 40% 宽度。

## 003 · 状态优先

宽 460。顶部只有一个 76pt 的 FPS 数字，下面两个全宽按钮，其余全部折叠成可展开行。

- hero 数字是唯一的视觉锚点，不和任何控件竞争
- 日常使用时只需要看「解锁了没」和「小窗开着没」
- 改设置要多点一次

适合：日常高频使用，追求视觉干净。

## 004 · 帧率小窗

三档尺寸都保持关闭按钮在右上角，实测 `右6, 上6` 完全一致。

- 默认：按钮完全透明，鼠标不移进来就看不到
- 悬停：变红底白叉，一眼能认
- 锁定：按钮收起，显示 `LOCK`；此时窗口点击穿透，只能 `Ctrl+Alt+F`

同时修正了掉帧配色（<60 转黄）和无数据状态（`--`）。

## 怎么选

| | 宽度 | 设置可见性 | 改动量 | 适合 |
|---|---|---|---|---|
| 001 严格网格 | 480 | 全部可见 | 最小 | 稳妥替换现有排版 |
| 002 双列 | 780 | 全部可见 | 中等 | 宽屏、一次看全 |
| 003 状态优先 | 460 | 折叠 | 中等 | 日常高强度使用 |

预览：直接用浏览器打开各目录下的 `index.html`。
